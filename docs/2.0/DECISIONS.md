# onot 2.0 Decision Log (ADR)

Lightweight ADR. Records choices that diverged from the plan, spike conclusions, and
deferred items, centered on the decision and its rationale. Format: ID / Decision /
Rationale / Impact. Unless noted otherwise, the date is 2026-06-02; refer to each PR
and the git history for implementation details and verification records.

---

## D-001 — Use venv+pip instead of uv for dependency tooling

- **Decision**: The primary reproducible environment is built with standard `python -m venv` + `pip` + pinned versions. Adopting `uv` is optional.
- **Rationale**: The work machine does not have `uv`, and using only standard tools lets us reproduce immediately without external installs while keeping portability.
- **Impact**: Plan §9.6, gate.sh.

## D-002 — New code is built in parallel with 1.x using src-layout (`src/onot/`)

- **Decision**: The 2.0 core is created fresh under `src/onot/`, and 1.x is moved to `legacy/onot/` to separate import paths (removal is a follow-up decision).
- **Rationale**: Parallel construction secures integration risk and rollback safety, and removes the shadow where root `onot/` masks `import onot`.
- **Impact**: Package layout, final acceptance criteria. (Removal is confirmed in D-017)

## D-003 — The 2.0 work branch base is main

- **Decision**: Milestone branches fork from the latest `main` (`feat/2.0-m<N>-<slug>`). The ban on direct commits to `main` remains in effect.
- **Rationale**: The latest commits are on `main` while `origin/dev` lags behind, so working on top of the most recent baseline reduces conflicts.
- **Impact**: Plan §9.6 branch strategy.

## D-004 — S1: license-expression / spdx-tools API confirmed

- **Decision**: Adopt the expression parsing of the two libraries and the SPDX 2.x document model as the basis for M2/M3 mapping (API verification complete).
- **Rationale**: Nested OR/AND and WITH exceptions are flattened correctly, `GPL-2.0+` is normalized to `GPL-2.0-or-later`, and unknown symbols are detected via `licensing.validate(...).errors`. The assumptions in plan §2, §3 hold. Evidence: `spikes/s1_license_spdx/`.
- **Impact**: M2 expression_parser/resolver, M3 SpdxAdapter.

## D-005 — SPDX 3.0 input is split off as a follow-up (deferred)

- **Decision**: The primary inputs are SPDX 2.x (JSON/YAML/Tag-Value/RDF), CycloneDX, and Excel. SPDX 3.0 input is split off as a follow-up.
- **Rationale**: spdx-tools 0.8.5 has no `spdx3.parser`, so 3.0 documents cannot be parsed. Resume when the library matures.
- **Impact**: Plan §2, TRACEABILITY R-S2/R-ING-1.

## D-006 — frozen resource access uses '/' chaining (no multi-argument joinpath)

- **Decision**: Bundled data is always accessed via `/` chaining, like `files("onot.license") / "data" / "licenses.json"`. Included in PyInstaller builds with `--add-data`/`--collect-data`.
- **Rationale**: In frozen builds, `files(pkg)` returns a `MultiplexedPath`, so multi-argument `joinpath` raises a `TypeError` (non-frozen is fine). Evidence: `spikes/s3_frozen/`.
- **Impact**: M2 catalog.py, M8 sidecar build. Resolves the core air-gap requirement risk.

## D-007 — The existing sample/ is not spec-compliant SPDX → use real SBOM fixtures

- **Decision**: SPDX adapter tests use spec-compliant fixtures generated by syft/cdxgen and similar tools, placed separately under `tests/fixtures/sbom/`. Only ExcelAdapter keeps processing the 1.x template xlsx.
- **Rationale**: The rdf/xlsx in the existing `sample/` are 1.x-only examples and fail spec parsing.
- **Impact**: M3 fixtures, TRACEABILITY R-ING-1.

## D-008 — The S4 (Electron sidecar) and S5 (PDF) spikes run at the start of M8

- **Decision**: Sequence the S4/S5 spikes that require the Electron toolchain as the first work of M8.
- **Rationale**: M1–M7 do not depend on this, and the sidecar's frozen-resource risk was already resolved in S3. This satisfies the "verify before building" principle.
- **Impact**: Plan §9.5, TRACEABILITY R-S4/R-S5.

## D-009 — Gate policy: triple gate L1+L2+L3 from M1

- **Decision**: M0.5 (skeleton slice) closes with L1+L3, and the triple gate including gate-verifier (L2) applies fully from M1.
- **Rationale**: M0.5 is a skeleton stage not included in M1–M9 of acceptance 9.9.
- **Impact**: Plan §9.1.

## D-010 — M2 license layer: bundling and normalization

- **Decision**: Vendor SPDX license-list-data v3.28.0 (727 licenses + 84 exceptions, full texts included) as a single file at `src/onot/license/data/licenses.json` (`scripts/update_license_data.py`). Adopt deprecated SPDX ids by normalizing them to canonical.
- **Rationale**: To fill in full texts in an air-gapped setting without a network. Normalization benefits notice quality. Online fetch is restricted to an SPDX id allowlist to block URL injection.
- **Impact**: Plan §3, M4 renderer.

## D-011 — M3 ingest: 4 adapters with auto-detection, XML security

- **Decision**: Provide SpdxAdapter (2.x), CycloneDxAdapter (JSON/XML), and ExcelAdapter, with detect/registry routing by extension and content sniffing (.json ambiguity resolved by content).
- **Rationale**: A regex guard was bypassed via UTF-16/32 encodings, so `_xml_guard` was hardened to inspect both the original and multiple encoding-decoded variants together (CDX uses defusedxml as a second defense). CDX named license slug collisions were resolved by suffix separation.
- **Impact**: Plan §2, M4 renderer.

## D-012 — M4 rendering: 4 renderers, i18n, themes

- **Decision**: Html/Text/Markdown/Pdf under the Renderer ABC. Jinja2 autoescape (HTML), separated theme CSS, and i18n via en/ko YAML catalogs. PDF uses WeasyPrint on web/CLI and Electron printToPDF on the installed app (M8).
- **Rationale**: A license_links substring substitution had a clobber where "MIT" was re-substituted inside "MITNFA", so it was replaced with regex tokenization. The i18n catalog is protected as immutable (MappingProxyType).
- **Impact**: Plan §4, §5, M5 CLI.

## D-013 — M5 CLI: multiple formats, auto-detection, exit codes

- **Decision**: `generate` (multiple `-f`, `--output-dir`, `--lang`, `--config`, `--offline/--online`, `--strict`, `--stdout`), `formats`, `version`. Exit codes are IngestError=2, LicenseError=3, ConfigError=4, other=1.
- **Rationale**: Unknown formats produce a clean message via pre-validation, and `--online` injects RemoteLicenseFetcher + DiskCache. Config precedence is CLI > yaml > env > default.
- **Impact**: Plan §6.4. M6 API reuses the same core.

## D-014 — M6 FastAPI sidecar

- **Decision**: Provide `/healthz`, `/api/formats`, `POST /api/parse`, and `POST /api/render` on the same core as the CLI. Stateless, processing uploads in temp files and discarding them. CORS allows only localhost/127.0.0.1.
- **Rationale**: Filenames use only the suffix to prevent traversal, XXE uploads return 400 via the ingest guard, and over-limit returns 413. OnotError is mapped to HTTP (Ingest 400, License 422, other 500).
- **Impact**: Plan §6.2. Used by the M7 frontend and M8 Electron.

## D-015 — M7 React frontend

- **Decision**: Vite + React 18 + TypeScript (strict) + Tailwind. shadcn-style components are written directly and Radix is not adopted (to stay lightweight). The preview iframe uses `sandbox=""`.
- **Rationale**: Reduces dependencies, and the iframe sandbox blocks preview scripts, providing double defense alongside backend autoescape. The download filename is taken from the backend value by parsing Content-Disposition.
- **Impact**: Plan §6.1. M8 Electron loads the static build.

## D-016 — M8 Electron shell + S4/S5 results

- **Decision**: Desktop PDF uses Electron `printToPDF` (an isolated offscreen window, `javascript:false`), and WeasyPrint is not bundled into the sidecar. The sidecar lifecycle is managed by a pure Node manager (findFreePort → spawn → /healthz polling → SIGTERM→SIGKILL).
- **Rationale**: In S4, an `onot-sidecar` built with PyInstaller `--collect-all` demonstrated parsing, air-gapped HTML rendering, and clean shutdown. WeasyPrint (GTK) is heavy and excluded. First startup is slow due to the macOS Gatekeeper scan, so the start timeout is 40s. External links are delegated to the system browser.
- **Impact**: Plan §6.3, §9.5. M9 CI packaging/E2E.

## D-017 — M9 CI + removal of 1.x legacy

- **Decision (CI)**: Replace the 1.x `python-app.yml` with `.github/workflows/ci.yml`. lint (ruff), test-core (ubuntu/windows/macos × py3.11–3.13, cov≥90), test-pdf, frontend (build+vitest), build-desktop (electron-builder + PyInstaller sidecar), e2e-desktop (Playwright-electron).
- **Decision (security CI)**: Remove the commercial Black Duck Detect and replace it with the open-source stack recommended by [TrustedOSS DevSecOps](https://trustedoss.github.io/devsecops/intro). Gitleaks (secret), Semgrep and CodeQL (SAST, CodeQL on a weekly cron), anchore sbom-action + grype (SCA, blocking at High and above). Containers (Trivy), IaC (Checkov), and DAST (ZAP) are excluded as there are no targets.
- **Decision (legacy)**: Remove 1.x remnants completely. Targets are `legacy/onot/`, `legacy/test/`, the root `setup.py`, `requirements.txt`, the 1.x output `output/`, the Excel samples `sample/` and `docs/how_to_prepare.md`, and the legacy mentions in the README.
- **Rationale**: History is traceable via git history, and removing the shadowing risk with src-layout and the repo confusion outweighs the benefit of preservation.
- **Impact**: Plan §8.4, final acceptance criteria.
